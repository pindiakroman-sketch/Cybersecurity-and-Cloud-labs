# What Happens When You Visit a Website?

- **Platform:** TryHackMe
- **Category:** Networking / Web Fundamentals
- **Level:** Beginner
- **Topics:** DNS, HTTP/HTTPS, Web Servers, Load Balancers, Databases

## Overview

This room helped me understand what happens behind the scenes when a browser loads a website. A single request can involve DNS resolution, network communication, web infrastructure, and server-side processing before the browser receives and renders the page.

## Request Flow

### 1. DNS Resolution

Before connecting to a website, the browser needs an IP address for its domain name. It may use a cached result or ask the configured DNS resolver.

If the answer is not cached, the DNS resolution process may involve root, TLD, and authoritative DNS servers.

### 2. Network Connection

Once the destination IP address is known, the client establishes communication with the server. The path may include a local router, intermediate networks, and security infrastructure.

Common web ports:

- **HTTP:** TCP port 80
- **HTTPS:** TCP port 443

HTTPS uses TLS to protect HTTP communication in transit.

### 3. Web Infrastructure

Depending on the website's architecture, the request may pass through a Web Application Firewall (WAF) and a load balancer.

- **WAF:** Inspects HTTP traffic and can block requests matching configured security rules.
- **Load balancer:** Distributes requests across available backend servers.

Not every website uses both components.

### 4. HTTP Request

The browser sends an HTTP request, for example:

```http
GET / HTTP/1.1
Host: example.com
```

The server processes the request and returns an HTTP response, which includes a status code, headers, and potentially a response body.

### 5. Application and Database

The web application determines what response to return. It may retrieve information from a database, such as product details or user data, but not every request requires a database query.

SQL can be used by applications to retrieve or modify relational database records.

### 6. Browser Rendering

The browser processes the returned HTML to construct the page. It may also request additional resources such as CSS, JavaScript, images, and fonts.

## Key Concepts

| Component | Purpose |
|---|---|
| DNS | Resolves domain names to IP addresses |
| IP | Provides logical addressing between networks |
| TCP | Provides a reliable, ordered byte stream |
| TLS | Protects data in transit when used with HTTPS |
| HTTP | Defines web requests and responses |
| WAF | Filters HTTP traffic according to security rules |
| Load balancer | Distributes traffic across backend servers |
| Web server | Handles HTTP requests and returns responses |
| Database | Stores and retrieves application data |
| Browser | Processes and renders web content |

## Security Relevance

Understanding the request flow helps explain where different web vulnerabilities can occur.

- **DNS:** Incorrect or malicious DNS configuration can direct users to an unexpected destination.
- **HTTP input handling:** Unsafely rendered user input can lead to HTML injection or, in certain cases, XSS.
- **Application and database:** Poorly constructed SQL queries can introduce SQL injection vulnerabilities.
- **Transport security:** HTTPS helps protect data in transit, but does not automatically make the application itself secure.

This provides a foundation for understanding web traffic in browser developer tools and packet captures, as well as for studying common web application vulnerabilities.
