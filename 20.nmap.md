# 🔍 Network Reconnaissance & Service Enumeration Lab (Nmap)

## 📌 Project Overview
This home lab demonstrates practical network discovery, port scanning, and service enumeration using **Nmap**. The goal of this exercise is to simulate the reconnaissance phase of a security assessment, understand how different scan types interact with network firewalls, and generate structured reports for vulnerability analysis.

## 🖥️ Lab Environment
* **Scanner Machine:** Linux (Kali / Ubuntu)
* **Target Machine:** Local Test VM (`192.168.1.X`) *(Nahraď svojou testovacou IP)*
* **Tools Used:** Nmap, Bash

---

## 🛠️ Methodology & Execution

### 1. Host Discovery
Before scanning ports, I identified live hosts on the subnet without sending intrusive port probes.
* **Command:** `nmap -sn 192.168.1.0/24`
* **Purpose:** Uses ICMP echo requests and ARP scans (on local networks) to map active devices.

### 2. Privilege Comparison: SYN Scan vs. TCP Connect Scan
I tested how Nmap behaves with and without root (`sudo`) privileges:
* **Unprivileged Scan:** `nmap -sT 192.168.1.X`
  * *Observation:* Without root access, Nmap cannot craft raw packets and defaults to a **TCP Connect Scan**, completing the full three-way handshake. This is noisier and easily logged by target systems.
* **Privileged Scan:** `sudo nmap -sS 192.168.1.X`
  * *Observation:* With `sudo`, Nmap performs a **TCP SYN Scan** (half-open scan). It sends a SYN packet and resets the connection upon receiving SYN-ACK, making it faster and stealthier.

### 3. Deep Enumeration (Ports, Services & OS)
To gather actionable intelligence on the target, I scanned all 65,535 TCP ports and enabled version and OS detection.
* **Command:** `sudo nmap -sS -sV -O -p- -Pn 192.168.1.X`
* **Key Flags Used:**
  * `-p-`: Scans all TCP ports (1–65535) instead of just the top 1000.
  * `-sV`: Probes open ports to determine exact service and version info.
  * `-O`: Performs OS fingerprinting.
  * `-Pn`: Treats the host as online, bypassing ICMP ping blocks.

### 4. Timing & Firewall Evasion Control
To avoid triggering Intrusion Detection Systems (IDS) or overwhelming slow networks, I tested timing templates:
* **Command:** `sudo nmap -sS -T2 --max-rate 50 192.168.1.X`
* **Purpose:** Uses the `polite` (`-T2`) timing template and restricts packet rate to 50 packets/second to minimize network footprint.

### 5. Reporting & Output Formatting
For documentation and integration with other security tools, I exported the scan results in all major formats simultaneously:
* **Command:** `sudo nmap -A -T4 192.168.1.X -oA scans/target_enumeration`
* **Generated Files:** `.nmap` (readable text), `.xml` (for parsing/importing into SIEM or vulnerability tools), and `.gnmap` (grepable format for Bash scripting).

## 📊 Key Findings & Blue Team Remediation
*(Tu doplň reálne porty, ktoré ti našlo, napr. Port 22 a Port 80)*

| Port | State | Service | Detected Version | Security Risk & Mitigation |
| :--- | :--- | :--- | :--- | :--- |
| **22/tcp** | Open | SSH | OpenSSH 8.9p1 | **Risk:** Brute-force attacks. **Fix:** Disable root login, enforce SSH key authentication, and restrict access via firewall. |
| **80/tcp** | Open | HTTP | Apache httpd 2.4.52 | **Risk:** Unencrypted traffic. **Fix:** Redirect all HTTP traffic to HTTPS (Port 443) and hide server version headers. |

## 💡 Lessons Learned
* Running Nmap with `sudo` is essential for raw packet manipulation (`-sS`, `-O`).
* Default scans miss non-standard ports; full port scans (`-p-`) are necessary for thorough audits.
* Proper output management (`-oA`) allows security analysts to quickly parse data using Linux tools like `grep` and `awk`.
