# Web Request Analysis Using Browser Developer Tools

## Lab Overview

- **Platform:** TryHackMe
- **Category:** Web Security / Network Analysis
- **Difficulty:** Beginner
- **Tools:** Web Browser Developer Tools, Network Tab
- **Focus:** HTTP requests, GET method, HTTP vs. HTTPS

## 1. Executive Summary

This lab introduced the use of browser Developer Tools to inspect web traffic and understand how a browser communicates with web servers. The investigation focused on examining network requests, identifying the HTTP GET method, and understanding the difference between HTTP and HTTPS.

## 2. Technical Investigation

### Step 1: Accessing Developer Tools

I opened the browser Developer Tools and navigated to the **Network** tab to inspect network activity generated by the web page.

The Network panel provides visibility into HTTP requests, response status codes, request headers, response headers, resource loading, and timing information.

### Step 2: Inspecting HTTP Requests

I examined the network requests generated during page loading and focused on the `GET` method.

The HTTP GET method is commonly used to retrieve resources from a web server.

Example of a basic HTTP request:

```http
GET / HTTP/1.1
Host: example.com
```

*Note: This is an illustrative example, not a captured request from the lab.*

### Step 3: Understanding HTTP and HTTPS

I explored the distinction between HTTP and HTTPS.

- **HTTP:** Application-layer protocol that does not provide transport encryption by itself.
- **HTTPS:** HTTP communication protected by TLS, providing encryption, integrity protection, and server authentication.

In a practical investigation, the protocol can be identified by examining the page URL and the details of the corresponding network request.

## 3. Findings

- Used browser Developer Tools to inspect web network activity.
- Examined HTTP requests and the purpose of the GET method.
- Reviewed the security differences between HTTP and HTTPS.
- No specific target URL, captured headers, response codes, or confirmed security vulnerabilities were recorded in the available notes.

## 4. Security Recommendations

1. **Enforce HTTPS:** Configure web applications to use valid TLS certificates and redirect HTTP traffic to HTTPS where appropriate.
2. **Protect Sensitive Information:** Avoid placing passwords, access tokens, and other sensitive data in URLs because URLs can appear in browser history, logs, and monitoring systems.
3. **Monitor Web Traffic:** Use browser Developer Tools and appropriate network analysis tools to investigate unexpected requests, response errors, and suspicious communication patterns.

## 5. Key Takeaways

This exercise provided practical exposure to browser-based network analysis and the fundamentals of HTTP communication. Understanding request methods, response metadata, and transport security is a useful foundation for further web security and SOC investigations.
