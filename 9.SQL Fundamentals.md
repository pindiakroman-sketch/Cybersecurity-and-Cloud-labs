## 1. Executive Summary

This lab introduced the fundamentals of relational databases and Structured Query Language (SQL). Using a café ordering system as an example, the exercises demonstrated how data is organised into tables and how SQL queries retrieve, filter, and sort records.

The lab also introduced basic database modification concepts and highlighted the importance of restricting unauthorised access to sensitive data.

## 2. Technical Investigation

### 2.1 Database Structure

A relational database stores structured information in tables.

- **Table:** A collection of related data, such as café orders.
- **Row:** A single record, such as one customer order.
- **Column:** An attribute of a record, such as an order ID, item name, or price.

Understanding this structure is essential when querying databases and investigating how applications store information.

### 2.2 Basic SQL Queries

The lab covered the following SQL clauses:

**SELECT — Retrieve data**

Specifies which columns should appear in the query results.

```sql
SELECT item, price
FROM orders;
```

**FROM — Specify the source table**

Identifies the table from which the data is retrieved.

```sql
SELECT *
FROM orders;
```

The `*` wildcard selects all columns.

**WHERE — Filter records**

Returns only records that match a specified condition.

```sql
SELECT *
FROM orders
WHERE price > 10;
```

**ORDER BY — Sort results**

Sorts records by a specified column. The default sort order is ascending; `DESC` specifies descending order.

```sql
SELECT *
FROM orders
ORDER BY price DESC;
```

These examples are illustrative and use an assumed table structure.

### 2.3 Database Modification and Security

SQL can also modify database contents. For example, `INSERT` adds records, `UPDATE` changes existing records, and `DELETE` removes records.

These operations can be legitimate administrative tasks, but unauthorised use can compromise data integrity.

If an attacker gains permission to modify café orders, they could alter prices, manipulate order records, or delete transactions. The impact depends on the attacker's privileges and the application's database design.

## 3. Findings

- Relational databases organise information into tables containing rows and columns.
- SQL provides a structured way to retrieve and work with database records.
- `SELECT` and `FROM` specify the data to retrieve and its source.
- `WHERE` filters records according to conditions.
- `ORDER BY` sorts query results.
- Unauthorised database modifications can affect data integrity and business operations.
- Database permissions should follow the principle of least privilege.

## 4. Remediation & Mitigation

- **Apply least privilege:** Give database accounts only the permissions required for their tasks.
- **Use parameterised queries:** Prevent user input from being interpreted as executable SQL in application queries.
- **Protect data integrity:** Restrict and monitor `INSERT`, `UPDATE`, and `DELETE` operations.
- **Audit database activity:** Record and review important queries and changes where appropriate.
- **Validate access controls:** Ensure users cannot access or modify records beyond their authorised scope.
- **Practise SQL:** Write queries using `SELECT`, `WHERE`, and `ORDER BY` against sample datasets.

### Key Takeaway

SQL enables applications and analysts to retrieve, filter, and sort structured data. Understanding basic queries provides a foundation for database administration, application security, and investigating potential data manipulation.
